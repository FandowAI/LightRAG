# 提示词管理页与迁移说明

管理页在 `/webui` 的“提示词”标签。它按文件理解、图谱入库、查询回答的业务顺序展示 10 张卡片、12 个运行变体；JSON 与分隔符文本抽取、续抽取分别占一个变体。默认按源码原样显示，保留换行、Markdown 标记、占位符和分隔线；点击卡片右上角“编辑”才切换到同一位置的编辑框。编辑时原按钮位置显示“发布生效”，其下拉菜单提供“保存草稿”和“取消编辑”；发布会先保存未保存的修改，再立即应用。旁边的“恢复当前配置默认”立即恢复此卡片的中文配置默认值，下拉菜单可直接恢复项目英文原版。灰色状态旁的 `ⓘ` 解释当前条件；切换解析规则、抽取格式或 VLM 配置并重启服务端后，页面从服务端重新读取状态，不需要按文件扩展名维护两套页面。

“已启用”表示当前路径会使用该模板；“按条件使用”表示还取决于文档内容、查询模式或处理阶段；“未启用”仍可查看、编辑、保存和发布，日后切换相应配置即可生效。状态依据当前服务端的 `LIGHTRAG_PARSER`、`ENTITY_EXTRACTION_USE_JSON`、`MAX_GLEANING`、`VLM_PROCESS_ENABLE` 和角色模型配置计算。它反映服务默认规则；单次上传附带的解析覆盖参数可能使该文件的实际路径不同。

服务启动时，未被自定义覆盖的字段直接使用项目内置中文版，**不需要先在页面保存或发布**。已有已发布覆盖优先生效；若配置了外部实体类型 YAML 或全局回答前缀，这些显式配置也保留。点击“发布生效”会自动保存当前修改再发布；也可以从下拉菜单只保存草稿，草稿不会影响运行请求。每张卡片只保留一份最新草稿。发布将改动应用到后续请求，并更新相关查询缓存标识。中文恢复会删除该卡片的已发布覆盖值和最新草稿，回到服务启动时的有效配置；英文恢复也清除草稿，并将项目英文原版写入数据库，立即用于后续请求。英文恢复会覆盖卡片内的外部实体类型配置字段；全局回答前缀始终按当前配置默认值恢复。英文原版来自项目自带的 `lightrag/prompt.py`、`lightrag/prompt_multimodal.py` 和 DOCX 智能标题模块；中文版在新增的 `lightrag/prompt_templates/zh/`。服务启动时将英文原版、中文内置版和当前配置默认版的全部 23 个字段同步到 SQLite；模板源码仍是默认版本的维护入口，已发布覆盖和草稿存于数据库。更新官方代码后如英文模板的占位符或行结构改变，应同步更新中文版，否则启动时会报错，避免悄悄使用不匹配模板。保存草稿、发布、恢复默认都会生成历史快照；页面右上角“版本历史”可载入旧快照到编辑器，再保存和发布，不会直接覆盖当前运行版本。历史记录包含时间、操作、操作者和该卡片的完整字段内容，按 workspace 存在数据库中，不按用户名分文件，也不会在恢复默认时删除。键入但尚未保存的内容只在当前浏览器会话中，刷新页面前应保存草稿；“取消编辑”会放弃尚未保存的修改，保留已有草稿。

发布时保留原模板的占位符是强制校验条件；示例列表在页面按条目显示原始源码，保存时自动还原为后端所需的字符串列表。23 个管理字段中，22 个有独立中文版文本；`user_prompt_prefix` 是默认空白的用户配置入口，恢复语言版本时按当前服务配置重置，不从英文或中文模板取值。共享字段（例如实体类型指导、初抽/补抽共用的系统指令和查询的用户前缀）出现在多个卡片中，发布或恢复其中一张卡片会影响所有使用该字段的路径。补抽卡片展示继承的系统指令、初抽用户指令和补抽指令；上一轮模型输出是运行时数据，不属于可编辑模板。

SQLite 数据库保存在 `<WORKING_DIR>/prompt_admin/prompts.sqlite3`；同一个数据库按 workspace 隔离数据。表 `prompt_templates` 存每个提示词的英文、中文、当前配置默认版，`prompt_active` 存已发布覆盖，`prompt_drafts` 存草稿及其基线，`prompt_history` 存完整修改历史，`prompt_state` 存修订号。升级后首次启动会自动导入原 `<WORKING_DIR>/prompt_admin/<workspace-hash>.json` 的覆盖、草稿、修订号和历史；旧 JSON 原样保留作为备份，之后以 SQLite 为准，不再写入 JSON。若数据库中已有该 workspace 的记录，就不会再次导入旧 JSON。此次变更需要重启 LightRAG 服务；以后发布提示词不需要重启。编辑要求已经配置 `AUTH_ACCOUNTS` 或 `LIGHTRAG_API_KEY`，且服务只用一个 worker。当前运行中的处理任务可能已读取旧模板，建议等入库空闲再发布。数据库包含提示词正文，应与其他服务配置一同备份。

为减少将来合并上游的冲突，主体逻辑位于新增的 `lightrag/prompt_admin.py`、`lightrag/prompt_admin_storage.py`、`lightrag/prompt_templates/zh/`、`lightrag/api/routers/prompt_admin_routes.py` 和 `lightrag_webui/src/features/PromptManager.tsx`。上游文件只承担接入：`lightrag/api/lightrag_server.py` 注册路由、`lightrag/operate.py` 引入缓存版本、`lightrag_webui/src/App.tsx` 与导航/Tab 类型接入新页面、`lightrag_webui/src/api/lightrag.ts` 导出共用请求实例、语言包新增文案。更新官方代码时优先保留这些接入点与新增文件；若官方更改了提示词名称或调用方式，再核对 `GROUPS` 字段映射。
